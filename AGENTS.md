# AGENTS.md

Notes for AI agents working in this repo. Keep entries terse; only record what code/docs can't tell you.

## Project
Clutch Marks — Cambridge IGCSE/AS/A2 revision platform (Vite + React + TS + Supabase). Maths 0580/9709, Physics 0625/9702, CS 0478/9618. The live Supabase DB is production — treat it as such.

## Environment & commands
- No Supabase CLI. All SQL goes through the Management API: `POST https://api.supabase.com/v1/projects/{REF}/database/query` with Bearer token `sbp_…` (read from `.freebuff/get-keys.cjs`); project ref + anon key come from `.env` (`VITE_SUPABASE_PROJECT_ID`, `VITE_SUPABASE_PUBLISHABLE_KEY`). Service key: `GET /v1/projects/{REF}/api-keys`.
- Use the bundled Bun, not npm: `BUN="$LOCALAPPDATA/Programs/@codebufffreebuff-desktop/resources/bun/bun.exe"`. Typecheck: `"$BUN" node_modules/typescript/bin/tsc --noEmit -p tsconfig.app.json`. No CI exists.
- Apply a SQL/migration file with a rollback dry run first: `node .freebuff/apply-sql-file.cjs <file.sql> [--apply]` (the live DB needs this; there is no Supabase CLI). `.freebuff/probe-*.sql` + `.freebuff/probe-*-live.cjs` are the read-only/live verifiers for each feature.
- Tests: `"$BUN" node_modules/vitest/vitest.mjs run` (vitest only collects `frontend/src/**/*.test.ts`). `frontend/src/lib/domainGuard.test.ts` fails on any tracked file matching `/clutchmarks\.com/i` outside its reasoned `EXEMPTIONS` list — the legacy `production/` bundle and `public/downloads/*.pdf` are exempt as generated artifacts (regenerate, don't hand-edit). Write the domain escaped in AGENTS.md/docs too, or the guard flags the doc.
- Dev server: Vite on port 8080; run doc `.freebuff/run.md`. On Windows, detach via PowerShell `Start-Process -FilePath 'npm.cmd' … -RedirectStandardOutput/-RedirectStandardError` (two different files).
- Deploy an edge function: `"$BUN" .freebuff/redeploy-manage-accounts.cjs <slug>` — multipart deploy, slug arg required, `verify_jwt: true`.
- Rebuild a topic's question bank against its own specification statements: `node .freebuff/build-topic-bank.cjs --topic <slug> [--apply]`, or `--all --apply --skip-applied`. It drafts through the `draft-content` function, gates and rotates the drafts, writes `.freebuff/drafts/<slug>.json` (the review artifact — read it, especially `blind_solve.items`), and only `--apply` writes. Workers AI has a **daily free neuron cap**: a full-estate run stops with `429 … used up your daily free allocation of 10,000 neurons`. Re-running with `--skip-applied` resumes; a topic whose draft file exists is reused rather than re-drafted.
- The `run_terminal_command` heredoc mangles backslashes/quotes in tricky strings; build such strings with `String.fromCharCode` or use file tools instead.
- Probes that simulate a JWT: a multi-statement `/database/query` request runs each statement in its own transaction, long `RAISE` messages come back truncated, and a caught `exception` reverts `set_config` made earlier in the same transaction — so set `request.jwt.claims` **inside** the block you assert from, keep the raised summary short, and prefer returning rows over raising.

## Database truth (critical)
- The live DB was built by direct SQL application — most of `supabase/migrations/` was never applied/recorded there. Never assume the migrations folder describes the live DB; introspect it first.
- `supabase/base.sql` is the golden full-schema snapshot (structure only, idempotent, validated by a BEGIN…ROLLBACK smoke test). After any schema change: apply live → add a migration file → regenerate with `"$BUN" .freebuff/golden-dump.cjs` (plain `node` cannot parse it: it uses top-level await) → re-smoke-test with `node .freebuff/smoke-base.cjs`.
- `frontend/src/integrations/supabase/types.ts` is hand-maintained — every new table/column/RPC must be added there manually or typecheck breaks. (The `@` alias is `frontend/src`, so `@/integrations/supabase/types` is this file; there is no `src/integrations/`.)
- `questions.statement_id` (`20261009220000`) is the only link from a question to the board statement it tests. `questions.objective_id` is a *different* thing — the per-topic teaching layer — and pointing a statement id at it violates the FK. `syllabus_coverage()` now reports `statement_questions` per row, so a topic whose whole bank sits on one of its four statements no longer reads as covered.
- `public.content_integrity_findings()` (`20261008150000`) is the admin-gated, **live-computed** content-health report behind `/admin/content-integrity`: U+FFFD in student-visible text, a `correct_option` that cannot point at the right option (0-based vs the legacy 1-based seeds), and `material_type` aliases. Extend it instead of writing another one-off content probe; its labels, order and repair links live in `frontend/src/lib/contentIntegrity.ts`.
- The damage that report hunts for is also refused at the table, not just reported: `20261009140000` adds `*_no_replacement_character` CHECKs (questions, quizzes, topics, lessons, study_materials, flashcards, flashcard_sets, past_papers, announcements) and `questions_answer_index_in_range`, and no role bypasses a CHECK the way `service_role` bypasses RLS. A console write that would store damage now fails — the copy for it lives in `frontend/src/lib/contentGuards.ts` (matched on the constraint name in PostgREST's `message`); restoring a `content_revisions` row taken before the encoding repair is refused for the same reason. Verify with `.freebuff/apply-sql-file.cjs .freebuff/probe-content-guards.sql` (dry run) and `.freebuff/probe-content-guard-live.cjs` (live, PostgREST).
- All curriculum content lives only in the live DB; seeders/exports are `.freebuff/content-*.cjs` + `.freebuff/seed-*.cjs`. There is no remote/backup yet (repo is local-only).

## Auth & security model
- `handle_new_user` (auth.users trigger, SECURITY DEFINER) seeds profile + `user_roles(role='student', is_approved=false)` and deliberately ignores client-sent role — never trust signup metadata for roles.
- `auth.admin.createUser` does NOT create role rows; `manage-accounts` must write `user_roles` explicitly (past bug: panel-created admins landed as students).
- Trigger `enforce_user_roles_writer` gates `user_roles` writes by `current_user` (service_role/postgres) or approved-admin `auth.uid()`; auth triggers run as `supabase_auth_admin`, so guards must allowlist by role name, not just `auth.uid()`.
- Edge functions run as service_role → normal audit triggers see a null actor; attribute mutations explicitly via the `audit_admin_action` RPC.
- Password policy: GoTrue global min length 6, `jwt_exp=1800`; admins 12+ & complexity enforced server-side in `manage-accounts`; students 6+ + complexity + HIBP k-anonymity check in `src/lib/passwordPolicy.ts`. Managed-config `password_hibp_enabled` is Pro-only (402) and the `required_characters` preset enum is broken server-side — don't retry config, enforce in code.
- Paid features are gated *server-side*, never by the browser: `public.has_active_plan(uid)` (admin-approved OR an active, unexpired `subscriptions` row) is the one predicate. EXECUTE is granted to `service_role` only — it takes an arbitrary uid, so an authenticated grant would let anyone probe anyone else's plan. RLS policies inline the same predicate instead. `ai-correction` refuses with 403 `{ code: "plan_required", upgrade: true }`; the client turns that into the upgrade card via `isPlanRequiredError()`.
- Student answer scripts go in the private `homework-uploads` bucket at `<user_id>/ai-marker/<uuid>.<ext>`. That shape is load-bearing twice over: the bucket's insert policy requires `storage.foldername(name)[1] = auth.uid()`, and `ai-correction` refuses any `answerFiles` path outside the caller's own folder (the IDOR guard). `frontend/src/lib/answerScripts.ts` is the only place that builds those paths.
- Signup email domains are restricted; create test accounts as `anything@igcse-platform.local` (`example.com` → 400).
- `auth.admin.deleteUser` cascades profile/role rows — capture identity before deleting (audit trail needs it).

## Gotchas (misleading errors)
- PostgREST embed `topics(name)` returns 400 if the FK is missing — embeds require real FKs (`flashcard_sets` lost its FK once and every list query 400'd).
- Generic PL/pgSQL triggers spanning multiple tables: `NEW.name` throws at runtime on tables without that column (broke announcement inserts with an unhelpful 400) — use `to_jsonb(NEW)->>'field'`.
- `pg_get_functiondef` output ends with a bare `$function$` line (no semicolon) — concatenating emitted SQL without terminating produces confusing downstream syntax errors.
- `ai_audit_log.action` has a CHECK constraint. `ai-correction` writes `'paper_correction'`, which the original constraint (`plan`,`correction`) rejected — every audit insert failed silently for months while the function reported success. When adding a new audit action, migrate the constraint in the same change (fixed for `paper_correction` by `20261008140000`).
- `login_lookup_throttle` table + `register_login_lookup` RPC back the `resolve-login-email` rate limiter; if the RPC is missing the limiter silently no-ops.
- `user_roles` PK is `id` only (no unique on `user_id`) — role rows can duplicate; admin checks use `.eq("role","admin").eq("is_approved",true)`.
- **Every edge function must call `Deno.serve(handler)`** (or export a default fetch handler). With only `export async function handler` the deploy still reports ACTIVE but the function is never dispatched: invocations hang with *no log entry at all* until the platform kills them at ~150s (opaque 504/546). `study-planner` shipped that way and had never worked.

## Content conventions
- Quiz answers are 0-based (`correct_option`); legacy seeds were 1-based and were fixed+rotated — any new seed content MUST use 0-based indices.
- Write a column vector as `(x; y)` — the lesson's own form ("Column vector (x; y); magnitude = √(x² + y²)"); points stay `A(1, 2)`. The old two-line bracket-piece art (`⎛⎝3⎞⎠` over `⎝2⎠`) silently loses its second row the moment it is copied into a single-line string, which is how the "Transformations and Vectors" addition row ended up with two identical options (repaired by `20261009120000`; check content with `.freebuff/probe-piece-scan.sql`).
- Crawler directives are build-enforced, not reviewed: `plugins/seoIndexDirectives.ts` reads every emitted `dist/**/index.html` plus `dist/spa-fallback.html` — the document `vercel.json`'s catch-all serves for any URL the build wrote no page for — and fails `npm run build` on an indexable fallback (or one claiming a canonical), a private page that is indexable, a `/auth`-style rule that contradicts the markup, or a route declared SPA-only in `frontend/src/lib/spaRoutes.ts` turning up as an indexable `ROUTE_META` entry (that would make the build write it a real file and stop the fallback answering it). Never `ROUTE_META` a route the app renders but the build cannot enumerate.
- Lessons are markdown stored in DB; `.cjs` content files are template literals — never put backticks in lesson text (broke parsing once; fixers in `.freebuff/fix-backticks*.cjs`).
- Student pages filter `material_type='notes'`; some admin paths wrote `'note'` — treat as aliases.
- Mastery is per objective, not per topic: `public.learning_objectives` (one row per thing a student must be able to do inside a topic, each with its own `teach` micro-lesson), `questions.objective_id`, and the `difficulty` vocabulary `check` / `drill` / `exam` (`medium` stays valid). Admin-gated-free but authenticated-only `public.topic_objective_mastery(topic)` reports the caller's own state — security invoker, no uid parameter. Applied 2026-10-09; the reference topic (`algebra-equations`) is seeded by `.freebuff/seed-objectives-algebra-equations.cjs` and verified by `node .freebuff/probe-objectives-live.cjs`. Shape, decisions and what is still missing: `docs/learning-objectives.md`. Note `questions` has no anon SELECT policy (only `quizzes` does), so objective/question reads must be authenticated, and `subject_levels.level` is an enum needing a cast against `text` columns.
- The authoring standard for that layer — objective format, tier rules, the worked example, the review gate — is `docs/objectives-authoring.md`. The gate is `node .freebuff/gate-objectives.cjs <topic-slug> | --all` (read-only, exit 1 on an error); `--self-test` proves each rule still rejects crafted bad content, so re-run it after editing the gate. Both flaws it has caught were real: all 12 correct answers on the reference topic sat at option 0, so the checks were guessable without the method (fixed by rotating the seeded positions — keep rotating them when editing a check), and 2.5b shipped two `### Method` sections against §3.1's five headings (fixed in the seeder; `teach_headings_wrong` now catches it). The gate is gitignored local tooling like the probes, but it is on `.gitignore`'s allow-list, so `git add .freebuff/gate-objectives.cjs` is all it takes to ship it.
- The A* layer is no longer theoretical: the topic-bank builder has shipped it for 13 topics (48 `exam`-tier questions and 13 `exam-technique` materials, up from 2 and 0). The extras a student reads *are* that `study_materials` row's `content` — `TopicNotes` renders a content-only material inline, because the notes library only lists `notes`/`summary` and the old "Read" link pointed at a page that did not contain it.
- `exam-technique` is a material type as of `20261009210000`; the coverage query has always aliased `exam_technique` to it, so both spellings are accepted.
- Model verification of drafts is a **signal, not a gate**. The builder's blind-solve pass sends each question with the key withheld (one call per batch) and stores the verdict per question in the draft file; it deliberately does *not* reject, because it was measured wrong in both directions — it agreed with a key that was arithmetically impossible, and it called a correct discriminant question "no option is correct". Read `blind_solve.items` before `--apply`; do not turn it into a hard check without new evidence.
- Flashcards don't exist for `statement_id`-linked content: the bank builder writes questions and one technique note per topic, nothing else.
- How that layer is meant to scale to the other 140 statements — an AI-assisted draft → machine-verify → human-review → seeder pipeline, with the model never writing a student-visible row — is designed but not built: `docs/objectives-authoring-pipeline.md`.
- The mastery loop sits on that layer (migration `20261009200000`): `public.objective_reviews` is the resurfacing schedule (ladder 1/3/7/16/35 days, server-written — students have no insert/update policy on it), advanced by a trigger on `practice_attempts`, which is why `grade_quiz` now also writes `practice_attempts` rows for objective-tagged questions (it used to write only `quiz_attempts`, so a checkpoint quiz moved nothing). Reads: `my_objective_mastery()`, `my_next_objective()` (one row, action `review`/`practise`/`start`) and `objective_review_questions()` — the last one deliberately omits `correct_option`. Rendered at `/mastery`; verified by `node .freebuff/probe-mastery-loop-live.cjs` (deterministic, resets the throwaway student first). Each objective's `teach` block is readable there too, rendered by `frontend/src/lib/objectiveTeach.ts` — a convert-on-render helper, deliberately not a markdown dependency (the lesson corpus in the DB is already HTML).
- "Every statement in the specification is covered" is a query, not a claim: `public.syllabus_statements` holds the boards' own subtopics (loaded + mapped by `.freebuff/content-syllabus-statements.cjs`, which refuses to seed a topic slug the DB lacks), and admin-gated `public.syllabus_coverage()` reports each one with `topic_ready` (notes ≥1000 chars + ≥15 questions) and `a_star_ready` (≥5 exam-tier questions + an exam-technique material). Rendered at `/admin/syllabus-coverage`; reasoning and per-spec status in `docs/syllabus-coverage.md`. Update mappings in the seeder, never in SQL by hand. All six specs are loaded now (278 statements: 0580 72, 0625 24, 0478 24, 9618 44, 9709 38, 9702 76), 259 mapped and 19 deliberately unmapped — logarithms/exponentials, numerical methods, differential equations and all of mechanics (9709), plus measurement/units, density, fundamental particles and the medical-physics option (9702). The coverage probe asserts that exact gap list, and fails if the list and the database disagree in *either* direction.
- The courses' AS/A2 maths and physics are **CAIE 9709/9702** — the topic slugs are 9709 Paper 1's eight subtopics in order and `.freebuff/content-as-math.cjs` says so in its header. The **past-paper archive holds Edexcel IAL papers** for those two levels (WMA11-13, WST01/02, WME01; Physics Units 1-6), and an earlier pass wired the outline extractor to Edexcel (YMA01/YPH01) on that basis, which would have measured coverage against a different qualification. That mismatch is unresolved and is the owner's call, not a mapping bug to paper over.
- `.freebuff/syllabus-outline.cjs` needs two CAIE parsers because the boards' tables differ: `caie-tabular` anchors on the sentence every subject-content row ends with ("Candidates should be able to:") for 0478/9618/9709/9702, while 0625 uses `caie-marked` on its Core/Supplement cell markers — running the anchor parser over 0625 yields **zero** rows, and the phrase appears just three times in that whole PDF. 0478 sets `bareAreas` because topics 7, 9 and 10 carry no subtopic code at all: the area number *is* the statement, and a `d.d`-shaped regex dropped three whole areas. Anchoring also repaired rows already live: three truncated 9618 titles and two 9702 statements (22.3, 23.2) that had silently vanished.
- `study-materials` bucket is private; open files via `openSignedFile` (`src/lib/contentFiles.ts`); preview PNGs live under `study-materials/previews/`.
- Brand assets (`public/icon-*.png`, `favicon.ico`, `og.png`, `brand/*`, `site.webmanifest`) are generated by `.freebuff/build-brand-assets.cjs` from the owner's artwork — regenerate, never hand-edit. Resize first, apply the rounded mask last: sharp doesn't premultiply, so masking before resizing rings pink/yellow along the alpha edge. `BrandMark`/`BrandLockup` render `brand/mark-512.png` (logo tile above the wordmark band).

No `LOVABLE_API_KEY` is set, so `study-planner` uses Cloudflare, and falls back to a deterministic offline plan (bounded 90s upstream call) rather than ever returning a 504.

It marks typed answers, photos of a handwritten script (Workers AI vision — `VISION_MODEL_CANDIDATES` is tried in order and the winner is cached per isolate; verify with `.freebuff/probe-ai-correction-live.cjs`) and text-layer PDFs, via a small in-function PDF extractor. A *scanned* PDF has no text layer, so it answers 422 and asks for photos. Re-run `node .freebuff/probe-ai-correction-live.cjs` after any change to it: it asserts the gate, upload isolation and both marking paths against the live project with throwaway accounts.
- Workers AI rejects retired/short model names outright ("No such model"; `llama-3.1-8b-instruct` died 2026-05-30). Both functions keep an alias map — send `@cf/…` ids or nothing and let the worker resolve.

## User preferences
- Notes must be exam-grade and syllabus-referenced, not simplified "explain-like-I'm-5" style.
- SaveMyExams-like UX: per-topic pages with SEO-friendly slugs (`/study/:subject/:level/:topic/notes|quiz|papers` via `src/lib/topicUrls.ts`); minimize clicks to reach anything.
- Security is the user's top concern (account takeover destroying content/reputation) — prefer defense in depth and verify changes live instead of assuming.
