# AGENTS.md

Notes for AI agents working in this repo. Keep entries terse; only record what code/docs can't tell you.

## Project
Clutch Marks — Cambridge IGCSE/AS/A2 revision platform (Vite + React + TS + Supabase). Six subjects: Maths 0580/9709, Physics 0625/9702, Chemistry 0620, Biology 0610, CS 0478/9618, and English (Cambridge 0500 First Language, OxfordAQA 9280 ESL). Copy that enumerates subjects is generated from `frontend/src/lib/subjectCatalogue.ts` — see Content conventions. The live Supabase DB is production — treat it as such.

## Environment & commands
- No Supabase CLI. All SQL goes through the Management API: `POST https://api.supabase.com/v1/projects/{REF}/database/query` with Bearer token `sbp_…` (read from `.freebuff/get-keys.cjs`); project ref + anon key come from `.env` (`VITE_SUPABASE_PROJECT_ID`, `VITE_SUPABASE_PUBLISHABLE_KEY`). Service key: `GET /v1/projects/{REF}/api-keys`.
- Use the bundled Bun, not npm: `BUN="$LOCALAPPDATA/Programs/@codebufffreebuff-desktop/resources/bun/bun.exe"`. Typecheck: `"$BUN" node_modules/typescript/bin/tsc --noEmit -p tsconfig.app.json`. No CI exists.
- Apply a SQL/migration file with a rollback dry run first: `node .freebuff/apply-sql-file.cjs <file.sql> [--apply]` (the live DB needs this; there is no Supabase CLI). `.freebuff/probe-*.sql` + `.freebuff/probe-*-live.cjs` are the read-only/live verifiers for each feature.
- Tests: `"$BUN" node_modules/vitest/vitest.mjs run` (vitest only collects `frontend/src/**/*.test.ts`). `frontend/src/lib/domainGuard.test.ts` fails on any tracked file matching `/clutchmarks\.com/i` outside its reasoned `EXEMPTIONS` list — the legacy `production/` bundle and `public/downloads/*.pdf` are exempt as generated artifacts (regenerate, don't hand-edit). Write the domain escaped in AGENTS.md/docs too, or the guard flags the doc.
- Dev server: Vite on port 8080; run doc `.freebuff/run.md`. On Windows, detach via PowerShell `Start-Process -FilePath 'npm.cmd' … -RedirectStandardOutput/-RedirectStandardError` (two different files).
- Deploy an edge function: `"$BUN" .freebuff/redeploy-manage-accounts.cjs <slug>` — multipart deploy, slug arg required, `verify_jwt: true`; add `--public` for a pre-auth function (`login-with-username`, `resolve-login-email`), where the default would make the login form itself require a token.
- Rebuild a topic's question bank against its own specification statements: `node .freebuff/build-topic-bank.cjs --topic <slug> [--apply]`, or `--all --apply --skip-applied`. It drafts through the `draft-content` function, gates and rotates the drafts, writes `.freebuff/drafts/<slug>.json` (the review artifact — read it, especially `blind_solve.items`), and only `--apply` writes. Workers AI has a **daily free neuron cap**: a full-estate run stops with `429 … used up your daily free allocation of 10,000 neurons`. Re-running with `--skip-applied` resumes; a topic whose draft file exists is reused rather than re-drafted.
- The `run_terminal_command` heredoc mangles backslashes/quotes in tricky strings; build such strings with `String.fromCharCode` or use file tools instead.
- Probes that simulate a JWT: a multi-statement `/database/query` request runs each statement in its own transaction, long `RAISE` messages come back truncated, and a caught `exception` reverts `set_config` made earlier in the same transaction — so set `request.jwt.claims` **inside** the block you assert from, keep the raised summary short, and prefer returning rows over raising.

## Database truth (critical)
- The live DB was built by direct SQL application — most of `supabase/migrations/` was never applied/recorded there. Never assume the migrations folder describes the live DB; introspect it first.
- `supabase/base.sql` is the golden full-schema snapshot (structure only, idempotent, validated by a BEGIN…ROLLBACK smoke test). After any schema change: apply live → add a migration file → regenerate with `"$BUN" .freebuff/golden-dump.cjs` (plain `node` cannot parse it: it uses top-level await) → re-smoke-test with `node .freebuff/smoke-base.cjs`.
- `frontend/src/integrations/supabase/types.ts` is hand-maintained — every new table/column/RPC must be added there manually or typecheck breaks. (The `@` alias is `frontend/src`, so `@/integrations/supabase/types` is this file; there is no `src/integrations/`.)
- `questions.statement_id` (`20261009220000`) is the only link from a question to the board statement it tests. `questions.objective_id` is a *different* thing — the per-topic teaching layer — and pointing a statement id at it violates the FK. `syllabus_coverage()` now reports `statement_questions` per row, so a topic whose whole bank sits on one of its four statements no longer reads as covered.
- `public.content_integrity_findings()` (`20261008150000`) is the admin-gated, **live-computed** content-health report behind `/admin/content-integrity`: U+FFFD in student-visible text, a `correct_option` that cannot point at the right option (0-based vs the legacy 1-based seeds), and `material_type` aliases. Extend it instead of writing another one-off content probe; its labels, order and repair links live in `frontend/src/lib/contentIntegrity.ts`.
- The damage that report hunts for is also refused at the table, not just reported: `20261009140000` adds `*_no_replacement_character` CHECKs (questions, quizzes, topics, lessons, study_materials, flashcards, flashcard_sets, past_papers, announcements) and `questions_answer_index_in_range`, and no role bypasses a CHECK the way `service_role` bypasses RLS. A console write that would store damage now fails — the copy for it lives in `frontend/src/lib/contentGuards.ts` (matched on the constraint name in PostgREST's `message`); restoring a `content_revisions` row taken before the encoding repair is refused for the same reason. Verify with `.freebuff/apply-sql-file.cjs .freebuff/probe-content-guards.sql` (dry run) and `.freebuff/probe-content-guard-live.cjs` (live, PostgREST).
- All curriculum content lives only in the live DB; seeders/exports are `.freebuff/content-*.cjs` + `.freebuff/seed-*.cjs`. There is no remote/backup yet (repo is local-only).

## Auth & security model
- `handle_new_user` (auth.users trigger, SECURITY DEFINER) seeds profile + `user_roles(role='student', is_approved=true)` and deliberately ignores client-sent role — never trust signup metadata for roles.
- Students may **change their own username** at `/settings` (`public.set_my_username`, migrations `20261022170000`/`20261022173000`): the row owner may set a canonical handle (`username_is_canonical` — lower-case, `[a-z0-9._-]`, 3–32), uniqueness is still `profiles_username_unique_idx`, and clearing a username stays admin-only because it frees the name and ends username login. The rules live once in `public.username_sanitize` (used by `handle_new_user`), `username_is_canonical` (used by the trigger and the RPC) and `frontend/src/lib/username.ts` (used by signup and the settings form). A self-service change writes a `self_service` row to `admin_audit_log`, so a released-then-claimed handle leaves a trail. A handle is displayed as `@name` everywhere, so the login form and `login-with-username` both strip a leading `@` before deciding whether the value is an email or a username (without that, typing `@sam` looked like an address and failed as one). Verified by `.freebuff/probe-username-selfservice-live.cjs` (27 checks: taken/invalid/unchanged, mixed-case direct write refused, clearing/email/owner changes refused, new handle logs in — plain, mixed-case and `@`-prefixed — and the old one stops, anon cannot execute the RPC).
- **One handle, one account — including under a race.** `profiles_username_unique_idx` is unique on `lower(username)` where username is not null, so no two students can hold `sam` and `Sam`, and a simultaneous claim is serialised by that index: two concurrent `set_my_username` calls give one `{ok:true}` and one `{error:"taken"}`, with the handle on exactly one row. Two holes sat either side of it. (1) Every identifier lookup passed the value straight to PostgREST `ilike`, and the canonical alphabet includes `_`, which SQL LIKE reads as "any single character" — measured live, a student holding `sam_1` **could not sign in** (401) because the pattern also matched `samx1`, and the raw lookup returned both rows. `login-with-username`, `resolve-login-email`, the console's duplicate checks and the parent dashboard's child-by-email lookup now escape through `likeLiteral` (edge functions) / `escapeLike` (`frontend/src/lib/username.ts`); the parent one mattered most, because the wrong match there links a stranger's child to a parent's dashboard. (2) `handle_new_user`'s EXISTS pre-check is a courtesy, not a lock: two sign-ups claiming the same handle at the same instant both passed it and the loser's INSERT escaped as GoTrue's opaque 500 "Database error saving new user". `20261022210000` retries the insert once with the id-derived suffix, so both accounts are created with distinct handles. Verified by `.freebuff/probe-username-shadow.cjs` (9 checks: the underscore handle signs in, the escaped lookup selects one row, two simultaneous claims give one winner and one `taken`, the handle stored on exactly one account) and `.freebuff/probe-signup-username-race.cjs` (run it more than once — the window is a millisecond wide). One pre-guard row still holds a mixed-case handle; the index is on `lower()`, so it cannot duplicate and every lookup is case-insensitive, so it was left alone.
- **`protect_profile_identity_fields` used to be a no-op.** It decided whether the caller was the service role with `current_setting('role')`/`session_user`, but it is `SECURITY DEFINER`, so both report the owner (`postgres`) for every caller: the disjunction was always true and the guard returned early. Measured live before the fix — a signed-in student could PATCH their own `profiles.email` (the recovery channel) and null their username through PostgREST. The fixed version keys off `auth.uid()`: a request with a `sub` is an end user, so only an admin may touch email/ownership/clearing; a service-role request has no `uid`. Same class of bug as `enforce_user_roles_writer` (see the admin lockdown entry) — never ask `current_user`/`role`/`session_user` who is calling from inside a definer function.
- Students may claim a username on the public signup form (`data.username`), so `handle_new_user` now treats that metadata as untrusted: it lower-cases, strips to `[a-z0-9._-]`, drops anything outside 3–32 chars, and suffixes a name already taken (case-insensitively) with 5 chars of the user id. That matters because `profiles_username_unique_idx` is unique on `lower(username)` and a duplicate inside the auth trigger surfaces as GoTrue's opaque "Database error saving new user" (500) — the signup would die. `login-with-username` resolves with `ilike`, so casing must never reach the table. Verified by `.freebuff/probe-signup-username-live.cjs`. Accounts are **auto-approved**: the signup approval gate was removed 2026-10-20 (policies + `is_user_approved()` + the client wall + the edge 403s, migrations `20261020080000`/`20261020081000`). `is_approved` remains only as a plan/privilege flag — `has_active_plan`'s admin exemption, approved-admin RLS reads, and the admin-only edge gates — never as an account gate.
- `auth.admin.createUser` does NOT create role rows; `manage-accounts` must write `user_roles` explicitly (past bug: panel-created admins landed as students). Its `create` action takes `role: student|parent` — a mapping that only special-cased `admin` made every "Parent" in the console a student (fixed 2026-10-22), and `role: "admin"` is now refused with 403. Passwords there are held to 12+ for admins and 8+ with lower/upper/digit/symbol for everyone else (stricter than 6+ self-signup) plus a HIBP check; the console pre-checks with `validatePassword(pw, role, 8)` so the form cannot promise less than the function enforces. `supabase.functions.invoke` throws away the function's own JSON on a non-2xx, so unwrap `error.context` (the console's `functionErrorMessage`) — otherwise every rejection reads as "Edge Function returned a non-2xx status code". Verified end-to-end by `.freebuff/probe-create-account-live.cjs`.
- **Admin access is owner-only and SQL-provisioned** (`20261022150000`). `user_roles` has no write policy for browser sessions at all — only SELECT policies (own row, parents verifying students, approved admins reading all). `enforce_user_roles_writer` refuses any insert/update/delete that touches an `admin` row once `auth.uid()` is set, and it keys off `auth.uid()` rather than `current_user`: the function is SECURITY DEFINER, so `current_user` is always its owner (postgres) and the old `current_user in ('service_role','postgres')` branch always returned early — RLS was the only real gate. The auth trigger still inserts its `student` row because it runs with no end-user JWT. `promote-admin` is deleted (source and deployment), the console has no promote/demote controls, and giving someone admin now means SQL. Verified by `.freebuff/probe-admin-lockdown-live.cjs` (9 checks: admin session cannot insert or update an admin row, student cannot self-promote, function 404, manage-accounts 403, `has_active_subscription` no longer callable by anon).
- **Admin authority needs a second factor** (`20261022180000`). A password alone signs in at AAL1, and AAL1 holds no admin power: `public.is_admin(uid)` = holds the admin role **and** `is_aal2()` (the `aal` claim of the request's access token), and every admin policy — 67 in `public`, 9 on `storage.objects` — plus six admin RPCs (`content_integrity_findings`, `syllabus_coverage`, the three paper-candidate functions, `protect_profile_identity_fields`) now ask it. The rewrite is generated from `pg_policies` and **refuses to commit** if any expression still grants admin without AAL2, so a new admin policy written the old way fails the next migration run — write `public.is_admin(auth.uid())`, never `has_role(auth.uid(), 'admin')`, in a policy. `has_role` stays pure membership. An AAL1 admin is deliberately no stronger than a student (own rows, public content, practice) so a lost phone cannot lock the owner out of the app, and the three student-facing exemption helpers (`ai_marker_quota_today`, `get_free_preview`, `get_student_questions`) still answer at AAL1. Recovery is SQL-only: `.freebuff/reset-admin-mfa.sql` (documented in `docs/admin-2fa.md`); sessions already issued keep `aal2` until their token expires (30 min). Edge functions that write with the service role cannot rely on RLS — `manage-accounts` and `generate-questions` decode the gateway-verified token and 403 with `{ code: "mfa_required" }` at AAL1. Verified by `.freebuff/probe-admin-mfa-live.cjs` (18 checks: AAL1 cannot read admin data/RPCs/write content/call the admin functions; the same calls pass after a real TOTP code, never enrolling the owner). UI: `/settings` card and the enroll-or-challenge gate in front of `/admin` (the gate, not a redirect — the owner must see they are one code away). Gitignore allows the probe through.
- **`fetchRole` reads every `user_roles` row, not one.** The PK is `id`, so a SQL-granted admin keeps the student row the signup trigger wrote; `maybeSingle()` answered that with 406 and null data, which hid the console from exactly the account that owns it (and would now hide the 2FA gate with it). Admin outranks parent, parent outranks student. `AdminRoute` also waits on `roleResolved`, because a hard reload of an `/admin/...` URL used to evaluate the guard before the role query returned and bounce to `/dashboard`.
- Edge functions run as service_role → normal audit triggers see a null actor; attribute mutations explicitly via the `audit_admin_action` RPC.
- Password policy: GoTrue global min length 6, `jwt_exp=1800`; admins 12+ & complexity enforced server-side in `manage-accounts`; students 6+ + complexity + HIBP k-anonymity check in `src/lib/passwordPolicy.ts`. Managed-config `password_hibp_enabled` is Pro-only (402) and the `required_characters` preset enum is broken server-side — don't retry config, enforce in code.
- Paid features are gated *server-side*, never by the browser: `public.has_active_plan(uid)` (admin-approved OR an active, unexpired `subscriptions` row) is the one predicate. EXECUTE is granted to `service_role` only — it takes an arbitrary uid, so an authenticated grant would let anyone probe anyone else's plan. RLS policies inline the same predicate instead. `ai-correction` refuses with 403 `{ code: "plan_required", upgrade: true }`; the client turns that into the upgrade card via `isPlanRequiredError()`.
- Student answer scripts go in the private `homework-uploads` bucket at `<user_id>/ai-marker/<uuid>.<ext>`. That shape is load-bearing twice over: the bucket's insert policy requires `storage.foldername(name)[1] = auth.uid()`, and `ai-correction` refuses any `answerFiles` path outside the caller's own folder (the IDOR guard). `frontend/src/lib/answerScripts.ts` is the only place that builds those paths.
- Signup email domains are restricted; create test accounts as `anything@igcse-platform.local` (`example.com` → 400).
- `auth.admin.deleteUser` cascades profile/role rows — capture identity before deleting (audit trail needs it).

## Payments & billing
- **Stripe owns subscriptions; the browser cannot write them.** `billing` (verify_jwt true) starts Checkout and opens the customer portal; `stripe-webhook` is deployed **`--public`** and authenticates with the `Stripe-Signature` HMAC — never relax that to "accept JSON", or anyone can POST themselves a plan. The student insert/update policies on `subscriptions` were dropped on purpose (`20261028120000`); the received-receipt flow and its two `homework-uploads/payments/*` storage policies are gone. The webhook re-reads each subscription from Stripe rather than trusting the event body, so replays are idempotent.
- **A trial is the product.** `has_active_plan()` and `has_active_subscription()` accept `('active','trialing')`, and `ai_correction`'s insert policy is the one place that inlines the predicate — change all three together. `useSubscription` mirrors it with `ACTIVE_SUB_STATUSES`; anywhere that tests `status === "active"` alone silently locks a trialing student out.
- **The 3-day trial is one number in two places** — `TRIAL_DAYS` in `supabase/functions/billing` (Deno, cannot import from the app) and in `frontend/src/lib/legal.ts`, which the pricing page and `/refunds` both read. `/refunds` is a legal document with its own version (`REFUND_POLICY_VERSION`); its promise (full refund of the first payment when asked within 3 days) has to stay true of what the webhook and Stripe actually do.
- **Never set `payment_method_types` on a Checkout Session.** Stripe now rejects it outright (`The payment_method_types parameter is no longer supported…`, yet another reminder that the API changes under this integration): methods come from the Dashboard's dynamic set. Dropping it did not lose Apple Pay — Apple Pay is a wallet inside card and still appears automatically — and card is enabled on the account. Restrict methods with a payment-method configuration in the Dashboard, not in code.
- **This project runs on a live key only.** A `sk_test_` key cannot charge the live Prices in `plans.stripe_price_id`, and a test subscription written by the webhook would grant real access because `subscriptions` has no mode column. Test mode was tried and removed on 2026-10-28; an `rk_` restricted key is not a substitute for `sk_live_` either (it may lack session/portal permissions). Catalog ids and the pending `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` secrets are in `docs/infrastructure.md`.

## Gotchas (misleading errors)
- **A `past_papers` row with no `paper_url` is not a broken row.** Biology, Chemistry and both English qualifications have 126 catalogue rows whose PDFs are not in the `past-papers` bucket; the page renders them as "Not in our library yet — open it on the board's site" and routes through `serve-external-paper`. Seeded by `.freebuff/seed-past-papers-bio-chem-eng.cjs`, which is idempotent on title + year + session. Conversely, an `INSERT`/`UPDATE` through the Management API answers `201` whether it matched zero rows or not — assert the count afterwards (`select length(content)`, `select count(*)`), never the status code. `docs/past-papers.md` holds the inventory.
- PostgREST embed `topics(name)` returns 400 if the FK is missing — embeds require real FKs (`flashcard_sets` lost its FK once and every list query 400'd).
- Generic PL/pgSQL triggers spanning multiple tables: `NEW.name` throws at runtime on tables without that column (broke announcement inserts with an unhelpful 400) — use `to_jsonb(NEW)->>'field'`.
- `pg_get_functiondef` output ends with a bare `$function$` line (no semicolon) — concatenating emitted SQL without terminating produces confusing downstream syntax errors.
- `ai_audit_log.action` has a CHECK constraint. `ai-correction` writes `'paper_correction'`, which the original constraint (`plan`,`correction`) rejected — every audit insert failed silently for months while the function reported success. When adding a new audit action, migrate the constraint in the same change (fixed for `paper_correction` by `20261008140000`).
- **A contact route is one literal: `SUPPORT_EMAIL` in `frontend/src/lib/support.ts`.** `site.ts` re-exports it as `SITE.supportEmail`; the legal notice, data-rights page, footer, sidebar, 404, crash boundary, settings note, 2FA reset copy, feedback form/dialog and the AI Marker's failure line all read the shared constant. `frontend/src/lib/email-config.test.ts` fails if any other file in `src`/`frontend/src` hard-codes the address, and it now reads the **deployed** function tree (`supabase/functions/...`) — the `backend/supabase/functions` copies are stale and a guard pointed at them proves nothing about what ships. The two outbound emails (`welcome-email`, `weekly-digest`) set `reply_to: SUPPORT_EMAIL` as well as printing it, because the sending identity (`onboarding@resend.dev` / `no-reply@`) is not a route anyone reads.
- `login_lookup_throttle` table + `register_login_lookup` RPC back the `resolve-login-email` rate limiter; if the RPC is missing the limiter silently no-ops.
- `user_roles` PK is `id` only (no unique on `user_id`) — role rows can duplicate; admin checks use `.eq("role","admin").eq("is_approved",true)`.
- **Every edge function must call `Deno.serve(handler)`** (or export a default fetch handler). With only `export async function handler` the deploy still reports ACTIVE but the function is never dispatched: invocations hang with *no log entry at all* until the platform kills them at ~150s (opaque 504/546). `study-planner` shipped that way and had never worked.
- **No student could submit a quiz**, twice over, and both faults only appear when the RPC actually runs. `grade_quiz` still called `public.is_user_approved()` after the approval gate was dropped (`20261020080000`), and it stored the inserted attempt's uuid in `_selected integer`, the variable that holds an option index — so `returning id into _selected` raised `invalid input syntax for type integer` even once the first fault was gone. `check_practice_answer` carried the same stale guard. Fixed by `20261025140000` + `20261025141000`; a SQL-level probe (set `request.jwt.claims`, call the RPC, re-raise with `pg_exception_context`) found both in one pass, which the toast's one-line message never could. `grade_quiz` is the one RPC a student hits every session — call it live after touching attempts, XP or the mastery triggers.
- **`react-helmet-async` 3.0.0 writes nothing at all** — no title, no meta tag, not even in jsdom — so a `<Helmet>`-managed head is only ever the prerendered one, and cleanup that removes the static tags leaves the live DOM with no description, canonical or robots. `frontend/src/components/SEOHead.tsx` now owns its tags directly (one `<meta>`/`<link>`/JSON-LD set, `data-seo="app"`, replaced on navigation and removed on unmount); `SEOHead.test.tsx` asserts the rendered head, not the source.

## Content conventions
- **An equation is written with symbols, and every symbol is defined.** The standard is a real glyph — Δ, λ, ρ, σ, ω, θ, ε₀, μ₀, π, √, ⇌, →, ², ³, ⁻¹ — never the English name: `p = rho g h`, `E = m c delta theta` and `v = f lambda` were all live in the Physics notes, inside `<pre><code>` blocks, and a student reading the body met the spelled form. Each equation carries an `<em>Key:</em>` line *inside the same `<p>`*, naming every symbol with its unit ("p = pressure (Pa); ρ = density (kg/m³); h = depth (m)"). Comparison operators are escaped glyphs (`&lt;`, `&gt;`), not "(less than)". The audit is read-only and covers notes, summaries and lessons: `node .freebuff/audit-note-formulas.cjs [subject] [--json out.json]`, which also lists spelled-out Greek and formula lines with no key. Sections are **appended**, never rewritten: `.freebuff/append-note-sections.cjs <module>` builds `content = content || section` guarded by id, `material_type` and a heading check, and `.freebuff/apply-note-text-fixes.cjs <module>` repairs a spelled symbol in place through an exact-string replacement that must match. Physics IGCSE's ten notes are at the bar (10/10 clean, 115 keyed equations), the five worst AS/A2 Physics notes joined them (118 keyed equations; Physics AS and A2 are 16/28 clean, all at the depth bar), and a first section each for Mathematics, Chemistry, Biology, Computer Science and both English specifications followed (81 more equations). The estate is 480 of 480 clean (340 notes/summaries + all 140 lessons), with 2,932 relations counted and a `<em>Key:</em>` on every row that carries one.
- **The audit's relation rule had to learn what is *not* an equation, and `--self-test` proves it still bites.** It originally counted any `=` line, so it reported a table's own `<table border="1">` attribute, SQL in a `<pre>` block, a method call and prose like `HTTPS = HTTP over TLS` as "formula lines but no symbol key" — 14 lesson rows that could only be "fixed" by keying nonsense. The rule now strips markup, requires a formula-shaped right-hand side (number, glyph, bracket or single letter after the `=`), skips a `<pre>`/`<code>` span *including its continuation lines* (a block only opens the tag on its first line), skips SQL clauses written inside prose, and skips a tautology (`1=1`). A reaction is also an equation: `2K + 2H₂O → 2KOH + H₂` counts, but only when chemical evidence (an element symbol with a count, or a subscript) sits within 24 characters of the arrow, because English prose uses arrows too (`QUOTATION → METHOD`) and a translation pipeline is not a reaction. "Mentions equations but writes none" no longer fires on a row that already carries a key or writes `CₙH₂ₙ`. `node .freebuff/audit-note-formulas.cjs --self-test` runs 17 positive and negative cases, including three lines that must be rejected; re-run it after editing the rule.
- **English has no formula sheet, and the audit already said so — the content did not.** An earlier pass appended an `<h2>Equations and symbols</h2>` section to four English notes (Prepositions and Collocations, Word Formation, FLL Analysing Language Choices, ESL Writing Tasks), framing method structures as `writer's effect = feature + connotation + reader response` with an `<em>Key:</em>` gloss under each. The audit exempts English (`EQUATION_FREE`), so nothing flagged it. `.freebuff/strip-english-formulas.cjs` rewrites those four sections as method sections — a subject heading (`The mapping rules, one page`, `Derivation patterns, one page`, `Structures the mark scheme rewards`), the `=` read as `is` (an em dash inside a bold structure line), each gloss on its own `<br>` — and it refuses to write while any ` = `, `<em>Key:</em>` or heading survives, while an h2/h3 is added or removed, or while the tag balance shifts by anything other than the removed `<em>` pairs. It transforms the **originals**, kept in `.freebuff-tmp/english-formulas-snapshot.json`, so a second run corrects the first instead of stacking; verify with `select count(*) filter (where content ilike '%Equations and symbols%') from study_materials` for the English subjects (must be 0).
- **A second, rule-based normaliser handles bodies whose notation is systematically wrong**, which hand-written pairs cannot: `.freebuff/normalise-note-notation.cjs` turns spelled Greek into glyphs, `6.63 x 10-34` into `6.63 × 10⁻³⁴` (the old form read as *ten minus thirty-four*), `m s-1` into `m s⁻¹`, `sqrt(` into `√(`, `->` into `→`, `deg C` into `°C`. Greek names and arrows apply to the whole body; powers, unit indices and `×` apply only inside `<pre><code>`. `--ids <id,id|file>` works on a list, `--all --kind notes,summary` (or `--lessons`) sweeps the estate, and every UPDATE carries `returning id` and asserts one row changed. Three separate guards were needed and each failed in its own way: a text fragment sliced backwards and stripped `<>`, so it looked for `codeT (K)` in a row holding `code>T (K)` and matched nothing; the API answered `201` with `[]` while nothing changed; and the md5 content hash that replaced it also survives the second run, which a fragment does not. The API throttles an estate sweep — retry on 429 with backoff, and space writes ~1s apart.
- **A `10` is only a power when the notation says so.** The first two versions of that normaliser matched a bare `10` followed by digits, and the estate sweep wrote 138 rows with them: `100 g` became `10⁰ g`, `108 000 J` became `10⁸ 000 J`, `18/60 x 100` became `18/60 × 10⁰`, and a chemistry worked example printed `40 + 12 + 48 = 10⁰`. The rule now needs a caret or a minus (`x 10^8`, `x 10-34`), plus the decimal-mantissa lossy form (`3.0 x 108`); fractional exponents keep their caret, because superscripting `10^2.4` gives `10².4`. Recovery was possible only because the audit had been run to JSON before the sweep: `--replay <audit.json>` re-derives every body from that snapshot, compares with the live row and repairs the difference — take a snapshot before any scripted content pass, and check `10⁰`/`10⁸ 000` after one.
- **A solved question shows the equation, then the substitution, then the result.** `Answer: 3` and `Answer: 40 ± 1.96 = (38.04, 41.96)` are both incomplete: the first states a value with no method, the second jumps from a formula to a pair of numbers. The house form is `SE = σ/√n = 15/√25 = 15/5 = 3` — relation, numbers in, result out — because the substitution is the step the mark scheme pays for and the step a student cannot reconstruct from a bare answer. Conceptual items are exempt (there is no equation in "define a Type II error"), and English solves by showing the technique and the model sentence rather than arithmetic. `node .freebuff/audit-answer-steps.cjs [subject] [--json out.json]` measures it read-only: of 615 solved answers in 79 materials, 362 show a relation and a substitution, 178 are conceptual, and 75 are short (31 jump to the result, 44 are a bare value). The rule counts a working as **two or more `=`** — one is a jump, none is a bare value — which is why a prose answer that happens to contain a digit can still read as short; judge those by eye instead of padding them with arithmetic, and expect the tail to be dominated by single-item notes and English technique answers that have no arithmetic to show. Repairs are exact-string modules through `.freebuff/apply-note-text-fixes.cjs`, in tranches by count: `.freebuff/content-answer-working-a.cjs` (Sampling and Estimation, Permutations and Combinations, Hypothesis Testing — the three worst at 10 of 10 compressed), then `-b.cjs` (44 answers across the five worst Mathematics notes) and `-c.cjs` (37 more: Binomial Distribution, Functions, Integration II, Transformations and Vectors, Complex Numbers). The `-b` tranche also corrected a real error rather than a terse one: a 2:1 section formula cannot give `(2; 3)` from `b = (6; 9)`, so the answer is now `(4; 6)` with the working that shows why. Tranches `.freebuff/content-answer-working-d.cjs` … `-k.cjs` took the count from 251 to 362 (2026-10-26), saying the relation out loud in statistics and mechanics where the old text went straight to the number (`mean = Σfx/Σf = …`, `s = ut + ½at² = …`). Two answers in `.freebuff/content-answer-working-j.cjs` were **damaged, not terse**: an earlier pipeline stripped `<`/`>` out of bodies, leaving `2x − 4 0 → x 2` and `b² − 4ac 0`, so they were restored as escaped glyphs in the same edit. `.freebuff/probe-stripped-operators.cjs` (read-only, with its `.sql`) hunts that signature estate-wide and found no other real case — every other hit is a legitimate `= 0 →`.

## User preferences
- Notes must be exam-grade and syllabus-referenced, not simplified "explain-like-I'm-5" style.
- SaveMyExams-like UX: per-topic pages with SEO-friendly slugs (`/study/:subject/:level/:topic/notes|quiz|papers` via `src/lib/topicUrls.ts`); minimize clicks to reach anything.
- Security is the user's top concern (account takeover destroying content/reputation) — prefer defense in depth and verify changes live instead of assuming.
